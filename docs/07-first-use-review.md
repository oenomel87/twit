# twit v2 첫 사용 후기와 2차 개선 목표

- 작성일: 2026-09-10
- 상태: 2차 개선 계획. 시범 사용에서 나온 후기를 정리하고, 사용자의 결정을 반영해 개선 범위를 확정한다. 2026-09-10에 사용자 정정(3장)과 Codex의 계획 검토(M-006)를 반영해 갱신했다. 설계 반영은 03·04 문서에, 실행 계획은 04 문서 13장에 있다.

## 1. 시범 사용 개요

2026-09-09에 Claude Code(`claude-1`)와 OpenCode(`opencode-1`)가 실제 메일함 `~/.twit`에서 한 대화(M-001부터 M-005)로 두 차례 왕복했다. 내용은 구현 커밋에 대한 리뷰 전달, 수정 결과 회신, 첫 사용자 질문, 답변과 반영이었다. 각 세션의 조회는 사람이 지시했고 twit은 어느 쪽도 실행하지 않았다.

이 문서의 후기는 `claude-1` 쪽에서 실제로 명령을 호출한 에이전트의 관점이다.

## 2. 사용 후기

### 2.1 잘 맞았던 점

- 명령이 의도와 1:1로 대응해 무엇을 호출할지 고민이 없었다. `inbox`, `read`, `reply` 세 개로 왕복이 끝났다.
- `thread --no-body`를 매번 사용했다. 읽지 않은 메시지 위치와 답장 체인을 한 화면에서 파악하고 필요한 한 건만 읽었다. 긴 리뷰 본문이 다시 출력되지 않아 문맥 사용량이 줄었다.
- JSON 봉투와 종료 코드가 예측 가능해 결과를 한 줄로 파싱하고 분기할 수 있었다.
- `--request-id`는 재시도할 일이 없었지만 붙여 두는 것만으로 중복 전송 걱정이 사라졌다.
- 오류 메시지가 다음 행동을 알려 줬다. 빈 메일함의 종료 코드 8을 보고 등록으로 바로 넘어갔다.

### 2.2 불편했던 점

| 번호 | 내용 | 처리 |
|---|---|---|

| 2 | 대화 안의 메시지가 모두 같은 제목이라 목록만으로는 어떤 내용의 답장인지 구분이 안 됐다 | 2차 개선 대상 |

## 3. 유지·제외 결정과 사용자 정정

시범 사용 뒤 사용자가 내린 결정이다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 답장 대기와 조회 시점 | 사람이 각 세션에 조회를 지시하는 현재 방식을 유지한다. 세션 훅 등 자동 조회를 두지 않는다 | 사람의 개입은 프로세스에 의도적으로 넣은 부분이다 |
| 역할 별칭(`--to @reviewer` 등) | 두지 않는다 | 역할은 남은 사용량을 보고 사람이 그때그때 정한다. 같은 모델이 문맥만 다른 상태로 다른 역할을 맡을 수도 있어 참여자와 역할을 고정할 수 없다 |
| 환경변수 역할 지정(`TWIT_REVIEWER` 등) | 두지 않는다 | 위와 같은 이유 |
| 프로젝트별 주소록 | 두지 않는다. 주소록은 전역이다 | 우선 전역으로 운영해 본다 |

### 3.1 사용자 정정: 자기 이름 환경변수와 사전 등록은 의도가 아니었다

Codex가 M-006으로 전한 사용자 원문은 다음과 같다.

> `TWIT_ACTOR`는 제가 처음 의도한 기능이 아닙니다. 저는 발신자와 수신자만 지정하려고 했지 역할을 부여할 생각은 없거든요. 그리고 ID를 엄격하게 관리할 생각도 없습니다. 중간 프로세스는 human in the loop로 제가 제어할 겁니다. 발신자를 그냥 codex, 수신자는 claude라고 합시다.

이 정정으로 이전 판의 "엄격한 참여자 ID 확인 관례"는 폐기한다. 이어서 사용자가 제안하고 확정한 방식은 다음과 같다.

- **주소록은 환경변수 하나다.** `TWIT_CONTACTS="dane,claude-code,codex,opencode"`처럼 셸 설정에 적는다. 전역이며 모든 에이전트가 같은 목록을 본다. 로컬에서는 많아야 네댓 개다.
- **에이전트가 자기 이름을 스스로 고른다.** `twit contacts`로 목록을 보고 자기 제품명과 맞는 항목을 선택한다. 없거나 둘 이상이면 사람에게 묻는다. 자기 이름 환경변수는 두지 않는다.
- **명령마다 이름을 명시한다.** `send`는 `--from`과 `--to`, 그 외 명령은 `--as`다.
- **목록에 없는 이름은 거절한다.** 등록 절차가 아니라 사람이 적어 둔 네댓 개와 대조하는 것이다. 오타로 인박스가 하나 더 생기는 일을 막는다.
- **항목은 이름만 나열한다.** 표시 이름이나 종류 같은 부가 정보는 두지 않는다.
- 참여자 등록 명령과 참여자 테이블, `whoami`는 없앤다. 과거 메시지의 이름은 그대로 남는다.

시범 사용에서 이 정정의 필요성이 실제로 드러났다. Codex가 `claude`에게 보낸 M-006을 `claude-1`로 조회하던 Claude Code는 인박스에서 찾지 못했고 DB를 직접 열어서야 발견했다. 등록된 이름이 여러 개 생기면 같은 일이 반복된다.

## 4. 2차 개선 목표

### 목표 0: 환경변수 주소록과 명시적 이름 지정

3.1의 결정을 구현한다. 다른 목표보다 먼저 한다. 03 문서 4장, 04 문서 3장(마이그레이션 2)·4장에 반영했다.

- `TWIT_CONTACTS` 해석과 검증, `--as`·`--from`·`--to`, `contacts` 출력 변경.
- 1차 구현의 `contacts` 테이블과 외래키를 없애는 마이그레이션. 기존 메시지는 유지한다.
- `--actor`와 `TWIT_ACTOR`, `whoami`, `contacts add` 제거.

검증: 목록에 없는 이름 거절과 목록 안내, 주소록 미설정 안내, 마이그레이션 후 1차 구현의 메시지 조회.

### 목표 1: 목록에 본문 첫 줄 미리보기

불편 2에 대응한다. `inbox`, `sent`, `thread --no-body`의 각 항목에 본문 첫 줄을 미리보기로 붙인다.

- 미리보기는 본문에서 공백이 아닌 첫 줄을 골라 앞뒤 공백을 제거한 것이다. 80자를 넘으면 80자에서 자르고 `…`를 붙인다.
- JSON에는 `preview` 필드로 넣는다. 본문은 여전히 목록에 포함하지 않는다.
- 텍스트 목록은 제목 뒤에 새 열로 붙이지 않고, 각 항목 아래에 들여쓴 줄로 표시한다. 한 항목이 두 줄이 되지만 제목 열의 잘림을 피한다.
- 03 문서의 "자르거나 요약하지 않는다"는 `--no-body`의 본문 길이 규칙이다. 미리보기는 본문이 아니라 목록 필드이므로 충돌하지 않지만, 03 문서 5.1과 5.5에 미리보기의 정의와 한계를 명시해 둔다.
- Markdown 제목 기호(`#`)로 시작하는 첫 줄은 그대로 둔다. 해석하지 않는다.
- 80자는 `body_length`와 같은 코드 포인트 기준이다. 정확히 80자면 생략 부호 없이, 초과하면 앞 80자 뒤에 `…`를 붙인다. LF와 CRLF를 모두 줄 구분으로 본다.
- `preview`는 목록 세 곳에만 있다. 본문을 돌려주는 `read`, `send`, `reply`, `thread` 응답에는 넣지 않는다. 구현에서 공통 메타데이터 변환과 목록 변환을 분리한다.
- 보낸함(`sent`)도 목록이므로 포함한다. 이전 판의 진행 순서에는 03 문서 5.6이 빠져 있었다.

검증: 선행 빈 줄과 공백, 한 줄뿐인 본문, 79·80·81자, 한글과 이모지, CRLF, Markdown 제목에서 미리보기가 규칙대로 나오고 `body_length`와 원문은 그대로인지 확인한다.

### 목표 2: 읽지 않은 메시지 일괄 읽기

불편 3에 대응한다. `read`가 여러 ID를 받고, `--unread` 옵션으로 기본 인박스의 읽지 않은 메시지를 한 번에 읽는다.

```sh
twit read M-004 M-005
twit read --unread
twit read --unread --json
```

- 여러 ID는 지정한 순서대로, `--unread`는 오래된 순서(`seq` 오름차순)로 반환한다. 대화 흐름을 따라 읽기 위해서다.
- 각 메시지에 `marked_read`를 개별로 붙인다. JSON은 `{ "messages": [ Message + marked_read ] }`다.
- 권한 검사는 메시지마다 한다. 여러 ID 중 하나라도 없거나 권한이 없으면 아무것도 읽음 처리하지 않고 오류를 낸다. 부분 성공을 두지 않는다.
- `--unread`는 ID와 함께 쓸 수 없다. 보관된 메시지는 포함하지 않는다.
- `--unread` 결과가 비어 있으면 빈 목록으로 정상 종료한다.
- 한 번에 여러 본문이 출력되므로 문맥 사용량이 커질 수 있다. 05 가이드에 "긴 본문이 예상되면 `inbox` 미리보기나 `thread --no-body`로 먼저 확인한 뒤 필요한 ID만 지정한다"를 적는다.
- 같은 ID를 두 번 지정하면 입력 오류다. ID와 `--unread`를 함께 주거나 둘 다 없는 경우도 같다.
- 전부 아니면 전무는 존재·권한 검사뿐 아니라 중간 UPDATE의 SQLite 오류에도 적용한다. 전체를 트랜잭션 하나로 묶는다.
- 단건 응답과 다건 응답의 JSON 구조를 `messages` 배열 하나로 통일하고 `schema_version`을 2로 올린다. 사용자가 에이전트 둘뿐인 지금이 호환성 비용이 가장 낮다. JSON 버전과 DB 마이그레이션 버전은 별개다.

검증: 읽지 않은 메시지 세 건 중 두 건을 ID로 읽으면 나머지 한 건은 그대로인지, 역순 ID 지정이 지정 순서로 나오는지, `--unread`가 보관된 미읽음 메시지를 건드리지 않는지, 권한 없는 ID가 섞이면 전부 미변경인지, 겹치는 ID를 두 프로세스가 동시에 읽어도 메시지별 `marked_read: true`가 한 번인지 확인한다.

### 목표 3: 자기 이름 고르기와 이름 지정 관례를 가이드에 반영

3.1의 방식을 05 가이드 1장 지침과 2장 설정에 적는다. 목표 0의 구현이 끝난 뒤 고친다. 그 전까지 05 가이드는 1차 구현의 명령을 그대로 안내한다.

- 1장 지침: "세션 시작 시 `twit contacts`로 목록을 보고 자기 제품명과 맞는 이름을 고른다. 없거나 둘 이상이면 사람에게 묻는다. 사람이 이름을 지정하면 그것을 쓴다. 수신자는 사람의 지시에 적힌 이름을 쓴다."
- 2장 설정: `TWIT_CONTACTS` 예시와 셸 설정 위치. `contacts add`와 `TWIT_ACTOR` 안내 제거.
- `~/.claude/skills/twit`의 드라이버와 설명도 새 명령에 맞춘다.

### 목표 4: 시범 사용에서 검증된 관례를 가이드에 고정

- 세션 마무리 시 상대에게 회신이 필요한지 여부를 본문에 명시한다. 예: "회신 불필요", "확인 답장 요청". 읽음 여부를 노출하지 않는 대신 본문으로 기대를 밝히는 관례다.
- 처리한 메시지는 보관해 인박스를 비운다는 규칙이 두 에이전트 모두에서 동작했음을 10장 기록으로 확인했으므로 1장 지침을 유지한다.

### 목표 5: Node 24와 내장 `node:sqlite`로 전환

Codex가 M-006에서 발견한 문제에서 출발했다. 기본 셸의 Node 24로 테스트하면 `better-sqlite3` 바이너리가 Node 22용이라 83개가 실패했고, 이후 다른 에이전트가 Node 24로 재빌드하자 이번에는 Node 22 셸의 Claude Code에서 CLI가 열리지 않았다. 네이티브 모듈이 Node 주 버전에 묶이는 한, 여러 에이전트가 각자 셸에서 twit을 부르는 이 프로젝트에서는 같은 일이 반복된다.

사용자 결정(2026-09-10): 코드베이스를 Node 24로 올리고 `better-sqlite3`를 Node 내장 `node:sqlite`로 바꾼다.

- 네이티브 모듈이 사라져 fnm으로 버전이 바뀌어도 재빌드가 없다. 런타임 의존성은 `commander` 하나가 된다.
- Node 24.12에서 `node:sqlite`가 `BEGIN IMMEDIATE`, 변경 행 수 등 twit이 쓰는 기능을 모두 제공함을 확인했다. 아직 실험 기능 경고를 내므로 진입점 shebang에서 그 경고만 끈다.
- API가 바뀔 위험은 SQLite 접근을 `store/db.ts` 한 파일에 모아 두는 것으로 감수한다.
- `.node-version`을 24로, `engines`를 `>=24`로 올린다. 세부는 04 문서 1장·3장·13장 1단계에 있다.

## 6. 진행 순서

2. 04 문서 1장, 2장, 3장, 4장, 5장, 6장, 7장, 8장, 10장, 12장을 갱신하고 13장에 실행 계획을 적는다. 완료.
3. 목표 0을 구현한다. 마이그레이션 2와 `.node-version`을 포함한다.
4. 목표 1, 2를 구현하고 회귀 테스트를 추가한다.
